# ras1c

Утилита на Go для инвентаризации кластера 1С:Предприятие через сервис **RAS**
(Remote Administration Server), по умолчанию порт **1545**.

Использует чистую Go-реализацию протокола RAS
([`github.com/khorevaa/ras-client`](https://github.com/khorevaa/ras-client)),
поэтому **не требует** установленной платформы 1С или утилиты `rac` на машине,
откуда запускается. Достаточно сетевого доступа до RAS-сервера. Только чтение.

## Сборка

```bash
cd ras1c
go mod tidy      # подтянет зависимости
go build -o ras1c .
```

Кросс-компиляция под Windows:

```bash
GOOS=windows GOARCH=amd64 go build -o ras1c.exe .
```

## Использование

```bash
# базово — инфобазы и сессии
./ras1c -host 10.0.0.5

# всё сразу
./ras1c -host 10.0.0.5 -user Администратор -password 'secret' -dump

# всё + детали по всем базам (нужна учётка админа инфобаз)
./ras1c -host 10.0.0.5 -dump -user Администратор -ib-user Администратор -json

# отдельные срезы
./ras1c -host 10.0.0.5 -processes -servers -locks
```

# выгрузить уникальные имена пользователей 1С из сессий в файл
./ras1c -host 10.0.0.5 -user Администратор -password 'secret' -export-users users.txt

# выгрузить уникальные хосты (NetBIOS/hostname) из сессий в файл
./ras1c -host 10.0.0.5 -user Администратор -password 'secret' -export-hosts hosts.txt
```

### Пароли через окружение

Чтобы пароли не светились в `ps` и истории shell:

```bash
export RAS1C_PASSWORD='secret'         # = -password
export RAS1C_IB_PASSWORD='ib_secret'   # = -ib-password
./ras1c -host 10.0.0.5 -dump -user Администратор -ib-user Администратор
```

Флаг имеет приоритет над переменной окружения.

### Флаги

| Флаг            | По умолчанию | Назначение |
|-----------------|--------------|------------|
| `-host`         | —            | IP или имя сервера RAS (**обязательно**) |
| `-port`         | `1545`       | порт RAS |
| `-user`         | пусто        | администратор кластера |
| `-password`     | пусто        | пароль администратора кластера (или env `RAS1C_PASSWORD`) |
| `-dump`         | `false`      | **выгрузить всё** — включает все срезы ниже разом |
| `-export-users` | пусто        | записать уникальные имена пользователей 1С из сессий в файл (построчно, без повторов) и выйти |
| `-export-hosts` | пусто        | записать уникальные хосты (NetBIOS/hostname) из сессий в файл (построчно, без повторов) и выйти |
| `-infobases`    | `true`       | список инфобаз |
| `-sessions`     | `true`       | список сессий |
| `-processes`    | `false`      | рабочие процессы rphost: хост, PID, память, соединения, нагрузка |
| `-admins`       | `false`      | администраторы кластера (тип аутентификации) |
| `-servers`      | `false`      | рабочие серверы: агент, порт кластера, диапазон портов, лимиты |
| `-connections`  | `false`      | соединения кластера |
| `-licenses`     | `false`      | лицензии, удерживаемые сессиями (колонка в таблице сессий) |
| `-locks`        | `false`      | блокировки кластера |
| `-infobase`     | пусто        | детали по одной инфобазе (по имени) |
| `-ib-user`      | пусто        | администратор инфобазы (для `-infobase` / `-dump`) |
| `-ib-password`  | пусто        | пароль администратора инфобазы (или env `RAS1C_IB_PASSWORD`) |
| `-json`         | `false`      | вывод в JSON |
| `-timeout`      | `60s`        | таймаут операции |

### Про `-dump`

`-dump` включает все read-only срезы: инфобазы, сессии (+ лицензии), процессы,
администраторы, рабочие серверы, соединения, блокировки. Если дополнительно
задать `-ib-user`/`-ib-password`, то в режиме dump подтягиваются **детали по
всем инфобазам** (СУБД, профиль безопасности, флаги блокировок). Для сбора в
файл удобно `-dump -json > dump.json`.

### Про `-export-users`

`-export-users <файл>` — отдельный режим: собирает имена пользователей
(`user_name`) из активных сессий всех кластеров, убирает повторы, сортирует и
записывает построчно в указанный файл, затем выходит (обычный отчёт не печатает).
Пустые имена (фоновые/системные сеансы без пользователя) пропускаются.
Требует `-user/-password`, если для кластера включено администрирование.

```bash
./ras1c -host 10.0.0.5 -user Администратор -password 'secret' -export-users users.txt
# → users.txt: по одному имени в строке, без дубликатов
```

### Про `-export-hosts`

`-export-hosts <файл>` — то же самое, но выгружает **имена хостов** (`host` из
сессии — NetBIOS/hostname рабочей станции клиента) построчно, без повторов.
Флаги `-export-users` и `-export-hosts` можно указать вместе — сессии
запрашиваются один раз, пишутся оба файла.

```bash
./ras1c -host 10.0.0.5 -user Администратор -password 'secret' \
        -export-users users.txt -export-hosts hosts.txt
```

Примечание: `host` — это имя клиентской машины, как его сообщает платформа
(обычно NetBIOS-имя). Не путать с `client_ip` (IP клиента, есть в таблице
сессий) и с хостом рабочего процесса.

## Что и откуда берётся

| Срез | Метод RAS | Требует аутентификации |
|------|-----------|------------------------|
| Кластеры + уровень безопасности | `GetClusters` | нет |
| Инфобазы (список) | `GetClusterInfobases` | админ кластера (если включено) |
| Сессии (+ лицензии) | `GetClusterSessions` | админ кластера (если включено) |
| Рабочие процессы rphost | `GetWorkingProcesses` | админ кластера |
| Администраторы кластера | `GetClusterAdmins` | админ кластера |
| Рабочие серверы | `GetWorkingServers` | админ кластера |
| Соединения | `GetClusterConnections` | админ кластера |
| Блокировки | `GetClusterLocks` | админ кластера |
| Детали инфобазы (СУБД, профиль, блокировки) | `GetInfobaseInfo` | **админ инфобазы** (`-ib-user/-ib-password`) |

## Замечания

- Порт **1545** — это RAS. Не путать с **1540** (`ragent`) и **1541** (менеджер
  кластера).
- Два уровня учёток: `-user/-password` — администратор **кластера**;
  `-ib-user/-ib-password` — администратор конкретной **инфобазы** (свои для каждой
  базы). Детали инфобазы без второй пары не отдаются.
- Если срез пустой без ошибки — вероятно, включено администрирование кластера:
  добавьте `-user/-password`.
- Библиотека сама согласует версию сервиса RAS при подключении; протестировано
  с платформой 8.3.x.
- `-timeout` поднят до 60с по умолчанию — на больших кластерах `-dump` может
  собирать данные дольше.

## Возможные доработки

- Опрос нескольких RAS-серверов из файла со списком адресов.
- Блокировки по инфобазе/сессии (`GetInfobaseLocks` / `GetSessionLocks`).
- Действия: завершение сессии, отключение соединения (сейчас утилита read-only).
