# 1C:Enterprise Web — Null/Weak Password Checker

Инструмент для аудита учётных записей 1С:Предприятие на отсутствие или слабые пароли через веб-интерфейс.  
Автоматизирует headless-браузер (Playwright), который проходит полный цикл проприетарной аутентификации 1С 8.3.24+, включая challenge-response с AES-шифрованным `cred`-блобом.

## Проблема

Начиная с версии **8.3.24**, веб-сервер 1С:Предприятие **не принимает** упрощённые методы аутентификации:

| Метод | Результат |
|---|---|
| `cred=base64(user:pass)` в URL | 402 — игнорируется |
| HTTP Basic Auth header | 402 — игнорируется |
| JSON body `{"usr":"...","pwd":"..."}` | 400 Bad Request |
| GET вместо POST | 405 Method Not Allowed |

Сервер принимает **только** зашифрованный `cred`-блоб, который конструирует JavaScript веб-клиента через трёхшаговый challenge-response:

```
1. POST /e1cib/login (пустое тело)                        → 402 + seanceID
2. POST /e1cib/login?sid=...  {"cred":"<AES blob>"}       → 200 + server challenge
3. POST /e1cib/login?sid=...  {"cred":"<response>"}       → 200 + сессия (успех)
```

Данный скрипт решает эту проблему, используя headless Chromium — браузерный JS сам конструирует `cred`-блоб, а скрипт перехватывает HTTP-ответы для определения результата.

## Как это работает

1. Для каждого пользователя открывается страница `?N=<username>&P=` — bootstrap.js 1С сохраняет credentials в `sessionStorage` и автоматически запускает аутентификацию
2. Скрипт перехватывает HTTP-ответы на `/e1cib/login` через Playwright response listener
3. Результат определяется по количеству и статус-кодам ответов:
   - **Несколько HTTP 200** — challenge-response пройден — пустой пароль подтверждён
   - **HTTP 402** — аутентификация отклонена — пароль установлен
   - **HTTP 400** — исчерпаны лицензии — остановка
4. После успешного входа выполняется logout для освобождения лицензии

```bash
pip install playwright
playwright install chromium
```


## Использование

```bash
# Проверка только пустых паролей
python3 1c-null-pass-fast.py http://10.101.81.111/toir users.txt

# Проверка пустых + словарь слабых паролей
python3 1c-null-pass-fast.py http://10.101.81.111/toir users.txt -w passwords.txt

# Только словарь (без проверки пустого пароля)
python3 1c-null-pass-fast.py http://10.101.81.111/toir users.txt -w passwords.txt --skip-empty

# Подробный вывод
python3 1c-null-pass-fast.py http://10.101.81.111/toir users.txt -w passwords.txt -v

# Сохранить результат в файл
python3 1c-null-pass-fast.py http://10.101.81.111/toir users.txt -w passwords.txt -v -o audit.txt

# Показать окно браузера (отладка)
python3 1c-null-pass-fast.py http://10.101.81.111/toir users.txt --headed

# Увеличить задержку (при License exhausted)
python3 1c-null-pass-fast.py http://10.101.81.111/toir users.txt -w passwords.txt --delay 3
```

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `target` | — | URL веб-приложения 1С (`http://host/base`) |
| `users` | — | Файл с именами пользователей (по одному на строку, UTF-8) |
| `-w`, `--wordlist` | — | Файл со словарём паролей (по одному на строку) |
| `-o`, `--output` | — | Сохранить найденные учётки в файл |
| `-v`, `--verbose` | `false` | Показывать результат для каждого пользователя |
| `--skip-empty` | `false` | Не проверять пустой пароль (только словарь) |
| `--headed` | `false` | Показать окно браузера |
| `--delay` | `0.5` | Задержка между попытками (секунды) |
| `--timeout` | `15` | Таймаут на аутентификацию (секунды) |

### Формат файлов

**Файл пользователей** — одно имя на строку (поддерживается кириллица):

```
proverkin
wsAdmin
АбраменковНВ
Баннов С.В.
```

**Файл словаря паролей** (`-w`) — один пароль на строку:

```
123123
password
qwerty
1234
admin
```

## Совместимость

| Версия 1С | Статус | Примечание |
|---|---|---|
| 8.3.24.x | Протестировано | Основная целевая версия |
| 8.3.22–23.x | Ожидается | Тот же bootstrap.js |
| 8.3.20 и ниже | Не проверено | Может использовать другой протокол |

Поддерживается развёртывание на IIS (основной сценарий) и Apache.

## Troubleshooting

**License exhausted / HTTP 400** — сервер 1С имеет ограниченное количество одновременных сессий. Увеличьте `--delay` до 3–5 секунд.

**Все пользователи — `no login response`** — проверьте доступность: `curl -s http://host/base/en_US/`. URL должен указывать на конкретную информационную базу (`/toir`, `/buh`, `/erp`).

**Таймауты** — увеличьте `--timeout` до 20–30 секунд. Первая загрузка веб-клиента 1С бывает медленной.

## Ограничения

- Требуется Playwright + Chromium (~200 MB)
- Скорость: ~3–5 секунд на пользователя (ограничение браузерной автоматизации)
- Потребляет лицензии 1С при успешном входе (освобождает через logout)
- При использовании `-w` время проверки увеличивается пропорционально размеру словаря
